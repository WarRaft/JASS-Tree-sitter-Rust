# JASS Tree-sitter Rust

Так, назва буквально описує стек — граматика Tree-sitter, написана на Rust.  
JASS винесено на перший план заради уваги (і ностальгії), і, звісно, ми його повністю підтримуємо.

## Підтримувані мови

### [JASS](https://github.com/WarRaft/tree-sitter-jass) — `.j`, `.pld`, `.ai`

Основна мова скриптів WarCraft III. Повна підтримка на основі спеціальної граматики
[tree-sitter-jass](https://github.com/WarRaft/tree-sitter-jass).

### [AngelScript](https://github.com/WarRaft/tree-sitter-as) — `.as`

Підтримка AngelScript для модифікації WarCraft III на базі UJAPI. Граматика —
[tree-sitter-as](https://github.com/WarRaft/tree-sitter-as).

### [BNI](https://github.com/WarRaft/tree-sitter-bni) — `.bni`

**BNI** (Blizzard Notation Ini) — структурований формат конфігурації для модифікації Warcraft III.  
Граматика — [tree-sitter-bni](https://github.com/WarRaft/tree-sitter-bni).

### BLP — `.blp`

Вбудований переглядач зображень формату **BLP**, що використовується у WarCraft III.

### SLK — `.slk`

Вбудований табличний редактор формату **SLK** (SYLK), який використовується у WarCraft III для зберігання ігрових даних.
Відображає дані в інтерактивній таблиці на canvas зі змінною шириною колонок, сортуванням та налаштовуваними прихованими стовпцями.
Налаштування (ширина колонок, приховані стовпці тощо) зберігаються безпосередньо у файлі. Перемикання між табличним та текстовим видом доступне через кнопку в заголовку редактора.

### DOO — `.doo`

Вбудований переглядач файлів розміщення **DOO** (`war3map.doo`, `war3mapUnits.doo`).
Відображає розміщення юнітів/дерев, позиції, rawcode та декорації кліфів у структурованій таблиці.

### W3I — `.w3i`

Вбудований переглядач файлів інформації про карту **W3I** (`war3map.w3i`).
Відображає метадані карти: назву, автора, гравців, сили, межі камери, налаштування туману/погоди, рандомні групи тощо.

### MPQ / W3X / W3M / W3N — `.mpq`, `.w3x`, `.w3m`, `.w3n`

Вбудований переглядач/браузер архівів **MPQ**, включно з файлами карт (`.w3x`, `.w3m`) та кампаній (`.w3n`) WarCraft III.
Надає віртуальну файлову систему для перегляду та відкриття файлів всередині архіву безпосередньо з провідника VS Code.

### WTS — `.wts`

Підтримка синтаксису для файлів **WTS** (WarCraft III Trigger Strings), що використовуються для локалізації.

## Система імпорту

Файли JASS можна зв'язувати між собою за допомогою спеціальних директив у коментарях:

```jass
//import path/to/file.j
//import! blizzard/common.j
//import-ujapi! ujapi/common.j
```

- `//import` — зв'язує файл зі спільною областю видимості. Усі декларації верхнього рівня (функції, глобальні змінні, типи, нативки) стають доступними.
- `//import!` — **заморожений** імпорт. Те саме, що `//import`, але цільовий файл вважається доступним лише для читання і не буде змінений рефакторингом чи автоперейменуванням.
- `//import-ujapi!` — **заморожений UjAPI-імпорт**. Завантажує та імпортує файл UjAPI. Якщо файл не існує локально, пропонується code action для завантаження.

Директиви мають знаходитися на самому початку файлу, до будь-яких інструкцій мови.

### Можливості імпорту

- **Автодоповнення шляху** — підказки для шляхів файлів після `//import`.
- **Ctrl+Click** — відкриває імпортований файл у редакторі.
- **Діагностика невалідних шляхів** — неіснуючі шляхи підсвічуються як помилки.
- **Автооновлення при перейменуванні/переміщенні** — при перейменуванні або переміщенні імпортованого файлу шляхи в усіх файлах, що посилаються, автоматично оновлюються.
- **Кросплатформні шляхи** — `/` і `\` взаємозамінні; підтримуються відносні, абсолютні та Windows-шляхи (`C://`).
- **Виявлення циклів** — циклічні імпорти виявляються та повідомляються.

## `//set` — Конфігурація файлу

```jass
//set hint ref type
//set build-jass ./out/war3map.j
//set build-as ./out/war3map.as
//set backup ./backup
```

| Ключ | Значення | Опис |
|------|----------|------|
| `hint` | `ref` `type` | Типи вбудованих підказок для відображення. `ref` — ID посилань (налагодження розв'язання символів), `type` — анотації типів (наприклад, `: integer`, `: constant real array`). Без директиви підказки не показуються (окрім ujapi). |
| `build-jass` | `<шлях>` | Шлях для JASS-збірки. Об'єднує все дерево імпортів в один `.j`-файл. Якщо шлях — директорія, додається `war3map.j`. Якщо шлях вказує на архів `.w3x` / `.w3m`, скрипт впроваджується прямо в карту. |
| `build-as` | `<шлях>` | Шлях для AngelScript-збірки. Та сама логіка об'єднання, але із синтаксисом `.as`. Конфлікти зарезервованих слів вирішуються додаванням числового суфікса. Якщо шлях вказує на архів `.w3x` / `.w3m`, скрипт впроваджується прямо в карту. |
| `backup` | `<шлях>` | Директорія для резервної копії архіву карти перед впровадженням. Перед модифікацією архіву зберігається копія з датою в імені (`YYYY_MM_DD_FileName.w3x`). |

## `//entry` — Точка входу збірки

```jass
//entry
//import common/natives.j
//set build-jass ./out/war3map.j
```

Директива `//entry` позначає файл як **корінь збірки** та область tree-shaking.

- Збірка починається з файлу `//entry`. Директиви `//set build-jass` / `//set build-as` враховуються лише у файлах з `//entry`.
- У вихідний файл збірки включаються лише файли, транзитивно доступні через `//import` від точки входу.
- Лише функції `main` / `config`, **оголошені у файлах з `//entry`**, вважаються живими коренями для аналізу невикористаних функцій.
- Якщо в проєкті немає жодної директиви `//entry`, зберігається стара поведінка: всі функції `main` / `config` вважаються точками входу скрізь.

---

## `//ignore` — Придушення діагностики для всього файлу

```jass
//ignore unused leak
```

Директива `//ignore` придушує цілі категорії діагностик для всього файлу. Має знаходитися на початку файлу, поряд з `//import` та `//set`.

На одному рядку можна вказати кілька тегів через пробіл. Підтримувані теги ті самі, що й для `//@ignore` (див. нижче).

---

## `//*` — Документуючі коментарі

Рядки, що починаються з `//*` безпосередньо перед оголошенням, вважаються **документуючими коментарями** (Markdown). Вони відображаються у спливаючих підказках та деталях автодоповнення.

```jass
//* Створює юніт у вказаній позиції.
//* Повертає handle створеного юніта.
function SpawnUnit takes integer id, real x, real y returns unit
    // ...
endfunction
```

Кілька послідовних рядків `//*` об'єднуються. Префікс `//* ` (з пробілом) видаляється; `//*текст` також допустимий.

---

## `//@ignore` — Придушення діагностики для оголошення

Коментар `//@ignore`, розміщений безпосередньо перед оголошенням функції, змінної, типу або native, придушує перелічені категорії діагностик для цього конкретного оголошення.

```jass
//@ignore unused
function HelperFunc takes nothing returns nothing
    // Діагностика «Unused function» для HelperFunc не буде показана.
endfunction
```

### Синтаксис

```jass
//@ignore тег1 тег2 ...
```

Теги розділяються пробілами. Підтримувані теги:

| Тег | Придушує |
|-----|----------|
| `unused` | Підказку «Unused function» |
| `leak` | Діагностику витоку хендлів — локальні змінні типу handle, не обнулені перед виходом з функції |
| `cycle` | Діагностику циклічних ланцюжків викликів |

`//@ignore` можна комбінувати з документуючими коментарями `//*` у будь-якому порядку:

```jass
//* Внутрішній хелпер — не викликається напряму.
//@ignore unused
function InternalHelper takes nothing returns nothing
endfunction
```

## Міжфайловий інтелект

Усі файли, зв'язані через `//import`, утворюють **зв'язний компонент** — спільну глобальну область видимості:

- **Резолвер області видимості** — постійний O(1) пошук імен по всіх імпортованих файлах, зберігається між перезапусками сервера.
- **Двофазне розв'язання** — Фаза 1 розв'язує символи локально; Фаза 2 зв'язує нерозв'язані посилання із символами з імпортів.
- **Відстеження змін експорту** — повторний розбір залежних файлів відбувається лише при реальній зміні набору експортованих декларацій.
- **Push-діагностика** — помилки повідомляються для затронутих файлів негайно, навіть якщо вони не відкриті в редакторі.

## Граф викликів

Сервер будує граф викликів функцій по всьому зв'язному компоненту:

- **Виявлення невикористаних функцій** — функції, недосяжні з точок входу `main` / `config`, позначаються.
- **Виявлення циклів** — циклічні ланцюжки викликів повідомляються через діагностику.
- **Топологічне сортування** — використовується системою збірки для розміщення викликаних функцій перед викликаючими (вимога JASS).

Панель **Граф викликів** на D3.js доступна через кнопку в заголовку редактора.

---

## Виявлення витоків хендлів

JASS не запускає деструктори для локальних змінних. Якщо локальна змінна типу handle містить ненульове посилання при виході з функції, об'єкт ніколи не звільняється — це **витік хендла**.

Сервер виконує аналіз потоку даних у кожному тілі функції для виявлення змінних типу handle, не обнулених (`set v = null`) перед кожною точкою виходу (`return` та неявний `endfunction`).

- **Швидке виправлення по змінній** — code action вставляє `set v = null` перед return.
- **Виправити всі витоки** — один code action виправляє всі витоки хендлів у файлі.
- Придушується через `//@ignore leak` (для функції) або `//ignore leak` (для всього файлу).

## Система збірки

Директиви `//set build-jass <шлях>` та `//set build-as <шлях>` запускають збірку, яка:

1. Збирає всі файли з дерева імпортів.
2. Виконує топологічне сортування функцій.
3. Об'єднує все в один вихідний файл: **типи → глобальні змінні → функції → `main`**.
4. Пропускає оголошення `native` та визначення типів (вони надаються рушієм).
5. Вільні вирази верхнього рівня поміщуються в `main`.

## Постійне кешування

Усі важкі структури даних серіалізуються на диск через **bincode** та відновлюються при перезапуску сервера:

- **Граф імпортів** — граф залежностей файлів (на базі petgraph).
- **Резолвер області видимості** — глобальний індекс символів.
- **Кеш символів** — декларації функцій/змінних/типів по файлах.
- **Кеш посилань** — карти посилань по файлах.

Це означає майже миттєвий запуск навіть для великих проєктів.

## Архітектура

- **Tree-sitter** — інкрементальний парсинг для всіх підтримуваних граматик.
- **`ParseSnapshot`** — атомарний незмінний знімок усіх LSP-даних файлу, зберігається в `Arc<ParseSnapshot>` для конкурентного читання без блокувань.
- **`CancellationToken`** — скасування по файлу: нові правки негайно переривають застарілі задачі парсингу.
- **DashMap** — конкурентне сховище файлів для всіх знімків.
- **petgraph** — аналіз графів імпортів та викликів.
