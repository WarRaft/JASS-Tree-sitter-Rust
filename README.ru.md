# JASS Tree-sitter Rust

Да, название буквально описывает стек — грамматика Tree-sitter, написанная на Rust.  
JASS вынесен на первый план ради внимания (и ностальгии), и, разумеется, мы его полностью поддерживаем.

## [VSCode](https://code.visualstudio.com)

Плагин объединяет различные инструменты для работы с классическим контентом WarCraft III: поддержка синтаксиса, функции редактора и несколько современных удобств.

## Поддерживаемые языки

### [JASS](https://github.com/WarRaft/tree-sitter-jass) — `.j`, `.pld`, `.ai`

Основной язык скриптов WarCraft III. Полная поддержка на основе специальной грамматики
[tree-sitter-jass](https://github.com/WarRaft/tree-sitter-jass).

### [AngelScript](https://github.com/WarRaft/tree-sitter-as) — `.as`

Поддержка AngelScript для моддинга WarCraft III на базе UJAPI. Грамматика —
[tree-sitter-as](https://github.com/WarRaft/tree-sitter-as).

### [BNI](https://github.com/WarRaft/tree-sitter-bni) — `.bni`

**BNI** (Blizzard Notation Ini) — структурированный формат конфигурации для моддинга Warcraft III.  
Грамматика — [tree-sitter-bni](https://github.com/WarRaft/tree-sitter-bni).

### BLP — `.blp`

Встроенный просмотрщик изображений формата **BLP**, используемого в WarCraft III.

### DOO — `.doo`

Встроенный просмотрщик файлов размещения **DOO** (`war3map.doo`, `war3mapUnits.doo`).
Отображает размещение юнитов/деревьев, позиции, rawcode и декорации клиффов в структурированной таблице.

### W3I — `.w3i`

Встроенный просмотрщик файлов информации о карте **W3I** (`war3map.w3i`).
Отображает метаданные карты: название, автор, игроки, силы, границы камеры, настройки тумана/погоды, рандомные группы и другое.

## Система импорта

Файлы JASS можно связывать между собой с помощью специальных директив в комментариях:

```jass
//import path/to/file.j
//import! blizzard/common.j
```

- `//import` — связывает файл с общей областью видимости. Все декларации верхнего уровня (функции, глобальные переменные, типы, нативки) становятся доступны.
- `//import!` — **замороженный** импорт. То же, что `//import`, но целевой файл считается доступным только для чтения и не будет изменён рефакторингом или автопереименованием.

Директивы должны находиться в самом начале файла, до любых инструкций языка.

### Возможности импорта

- **Автодополнение пути** — подсказки для путей файлов после `//import`.
- **Ctrl+Click** — открывает импортируемый файл в редакторе.
- **Диагностика невалидных путей** — несуществующие пути подсвечиваются как ошибки.
- **Автообновление при переименовании/перемещении** — при переименовании или перемещении импортируемого файла пути во всех ссылающихся файлах автоматически обновляются.
- **Кроссплатформенные пути** — `/` и `\` взаимозаменяемы; поддерживаются относительные, абсолютные и Windows-пути (`C://`).
- **Обнаружение циклов** — циклические импорты обнаруживаются и сообщаются.

## `//set` — Конфигурация файла

```jass
//set ref-tip 1
//set build-jass ./out/war3map.j
//set build-as ./out/war3map.as
//set unused 0
```

| Ключ | Значения | Описание |
|------|----------|----------|
| `ref-tip` | `1` / `0` | Показать / скрыть встроенные подсказки с ID ссылок рядом с каждым идентификатором — полезно для отладки разрешения символов. |
| `unused` | `1` / `0` | Включить / отключить диагностику неиспользуемых функций для всего файла. По умолчанию `1` (включено). |
| `build-jass` | `<путь>` | Путь для JASS-сборки. Объединяет всё дерево импортов в один `.j`-файл. |
| `build-as` | `<путь>` | Путь для AngelScript-сборки. Та же логика объединения, но с синтаксисом `.as`. |

## `//*` — Документирующие комментарии

Строки, начинающиеся с `//*` непосредственно перед объявлением, считаются **документирующими комментариями** (Markdown). Они отображаются во всплывающих подсказках и деталях автодополнения.

```jass
//* Создаёт юнит в указанной позиции.
//* Возвращает handle созданного юнита.
function SpawnUnit takes integer id, real x, real y returns unit
    // ...
endfunction
```

Несколько последовательных строк `//*` объединяются. Префикс `//* ` (с пробелом) удаляется; `//*текст` тоже допустим.

---

## `//@ignore` — Подавление диагностики для объявления

Комментарий `//@ignore`, размещённый непосредственно перед объявлением функции, переменной, типа или native, подавляет перечисленные категории диагностик для этого конкретного объявления.

```jass
//@ignore unused
function HelperFunc takes nothing returns nothing
    // Диагностика «Unused function» для HelperFunc не будет показана.
endfunction
```

### Синтаксис

```jass
//@ignore тег1 тег2 ...
```

Теги разделяются пробелами. Поддерживаемые теги:

| Тег | Подавляет |
|-----|-----------|
| `unused` | Подсказку «Unused function» |

`//@ignore` можно комбинировать с документирующими комментариями `//*` в любом порядке:

```jass
//* Внутренний хелпер — не вызывается напрямую.
//@ignore unused
function InternalHelper takes nothing returns nothing
endfunction
```

## Межфайловый интеллект

Все файлы, связанные через `//import`, образуют **связный компонент** — общую глобальную область видимости:

- **Резолвер области видимости** — постоянный O(1) поиск имён по всем импортированным файлам, сохраняется между перезапусками сервера.
- **Двухфазное разрешение** — Фаза 1 разрешает символы локально; Фаза 2 связывает неразрешённые ссылки с символами из импортов.
- **Отслеживание изменений экспорта** — повторный разбор зависимых файлов происходит только при реальном изменении набора экспортируемых деклараций.
- **Push-диагностика** — ошибки сообщаются для затронутых файлов немедленно, даже если они не открыты в редакторе.

## Граф вызовов

Сервер строит граф вызовов функций по всему связному компоненту:

- **Обнаружение неиспользуемых функций** — функции, недостижимые из точек входа `main` / `config`, помечаются.
- **Обнаружение циклов** — циклические цепочки вызовов сообщаются через диагностику.
- **Топологическая сортировка** — используется системой сборки для размещения вызываемых функций перед вызывающими (требование JASS).

Панель **Граф вызовов** на D3.js доступна через кнопку в заголовке редактора.

## Визуализация графа импортов

Панель **Граф импортов** на D3.js показывает дерево зависимостей текущего файла. Доступна через кнопку в заголовке редактора. Все ресурсы визуализации встроены — подключение к интернету не требуется.

## Система сборки

Директивы `//set build-jass <путь>` и `//set build-as <путь>` запускают сборку, которая:

1. Собирает все файлы из дерева импортов.
2. Выполняет топологическую сортировку функций.
3. Объединяет всё в один выходной файл: **типы → глобальные переменные → функции → `main`**.
4. Пропускает объявления `native` и определения типов (они предоставляются движком).
5. Свободные выражения верхнего уровня помещаются в `main`.

## Постоянное кеширование

Все тяжёлые структуры данных сериализуются на диск через **bincode** и восстанавливаются при перезапуске сервера:

- **Граф импортов** — граф зависимостей файлов (на базе petgraph).
- **Резолвер области видимости** — глобальный индекс символов.
- **Кеш символов** — декларации функций/переменных/типов по файлам.
- **Кеш ссылок** — карты ссылок по файлам.

Это означает почти мгновенный запуск даже для больших проектов.

## Архитектура

- **Tree-sitter** — инкрементальный парсинг для всех поддерживаемых грамматик.
- **`ParseSnapshot`** — атомарный неизменяемый снимок всех LSP-данных файла, хранится в `Arc<ParseSnapshot>` для конкурентного чтения без блокировок.
- **`CancellationToken`** — отмена по файлу: новые правки немедленно прерывают устаревшие задачи парсинга.
- **DashMap** — конкурентное хранилище файлов для всех снимков.
- **petgraph** — анализ графов импортов и вызовов.

## Горячие клавиши

Все команды доступны через кнопки в заголовке редактора, но вы также можете назначить собственные горячие клавиши.

Откройте **Сочетания клавиш** (`Ctrl+K Ctrl+S` / `⌘K ⌘S`), найдите нужную команду и назначьте любую комбинацию.

| ID команды | Описание |
|------------|----------|
| `importGraph.show` | Показать граф импортов |
| `callGraph.show` | Показать граф вызовов |
| `typeGraph.show` | Показать граф типов |
| `rescan.execute` | Перечитать все файлы |
| `build.execute` | Сборка (JASS / AngelScript) |

Или добавьте привязки напрямую в `keybindings.json` (`Ctrl+Shift+P` → *Preferences: Open Keyboard Shortcuts (JSON)*):

```json
[
  { "key": "ctrl+shift+i", "command": "importGraph.show",  "when": "resourceLangId == jass || resourceLangId == angelscript" },
  { "key": "ctrl+shift+g", "command": "callGraph.show",    "when": "resourceLangId == jass || resourceLangId == angelscript" },
  { "key": "ctrl+shift+t", "command": "typeGraph.show",    "when": "resourceLangId == jass || resourceLangId == angelscript" },
  { "key": "ctrl+shift+r", "command": "rescan.execute",    "when": "resourceLangId == jass || resourceLangId == angelscript" },
  { "key": "ctrl+shift+b", "command": "build.execute",     "when": "resourceLangId == jass || resourceLangId == angelscript" }
]
```
