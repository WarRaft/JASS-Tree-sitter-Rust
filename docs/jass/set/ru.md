# `//set` — Директива настройки файла

Директива `//set` позволяет настраивать параметры языкового сервера для
конкретного файла.  Она должна находиться **в самом начале** файла,
рядом с директивами `//import`, до любых языковых конструкций.

## Синтаксис

```jass
//set <ключ> <значение>
```

* Токен `//set` должен начинаться с **колонки 0** (без ведущих пробелов).
* `<ключ>` — имя настройки (пробелы в ключе не допускаются).
* `<значение>` — всё после ключа до конца строки (пробелы обрезаются).

## Пример

```jass
//import common/natives.j
//set hint ref type
//set lens fn

globals
    integer count = 0
endglobals
```

## Доступные настройки

| Ключ | Тип | По умолч. | Описание |
|------|-----|-----------|----------|
| `hint` | `ref` `type` | | Типы встроенных подсказок для отображения. `ref` — ID ссылок (для отладки разрешения символов), `type` — аннотации типов (напр. `: integer`, `: constant real array`). Без директивы подсказки не показываются (кроме ujapi). |
| `lens` | `fn` `var` `arg` | | Линзы кода над объявлениями. `fn` — счётчик ссылок над функциями/native, `var` — над переменными (глобальные + локальные), `arg` — над параметрами функций. Без директивы линзы не показываются. |
| `build-jass` | `<путь>` | `./` | Путь для сборки JASS. Объединяет всё дерево импортов в один `.j` файл: типы → native → globals → функции (в топологическом порядке) → `main`. Если путь — директория, добавляется `war3map.j`. Если путь указывает на `.w3x` или `.w3m` архив, скрипт записывается прямо в карту. |
| `build-as` | `<путь>` | `./` | Путь для сборки AngelScript. Та же логика слияния, но с синтаксисом `.as`. Конфликты с зарезервированными словами разрешаются добавлением числового суффикса. Если путь указывает на `.w3x` или `.w3m` архив, скрипт записывается прямо в карту. |
| `backup` | `<путь>` | `./` | Путь для резервной копии карты. Перед записью скрипта в `.w3x` / `.w3m` файл, копия оригинального архива сохраняется по этому пути с префиксом даты: `YYYY_MM_DD_ИмяФайла.w3x`. Если путь — директория, файл с датированным именем помещается в неё. |
| `build-uglify` | `0 \| 1` | `0` | Минифицировать идентификаторы в сборке. При включении имена функций и переменных сокращаются для уменьшения размера файла. |
| `build-before` | `<команда>` | | Команда терминала, выполняемая **перед** сборкой. Запускается через `sh -c` (Unix) или `cmd /C` (Windows). Рабочая директория — каталог файла `//entry`. Поддерживает шаблонные переменные `{{переменная}}` (см. ниже). |
| `build-after` | `<команда>` | | Команда терминала, выполняемая **после** сборки (только при успехе). Те же правила выполнения, что и у `build-before`. |

## Шаблонные переменные

Команды `build-before` и `build-after` поддерживают подстановки
`{{переменная}}`, которые раскрываются в полные нормализованные пути
перед выполнением. Это позволяет надёжно передавать пути сборки
во внешние скрипты.

| Переменная | Описание |
|------------|----------|
| `{{entry}}` | Полный нормализованный путь к файлу `//entry`. |
| `{{entry-dir}}` | Полный нормализованный путь к каталогу, содержащему файл `//entry`. |
| `{{target-jass}}` | Полный нормализованный путь к файлу сборки JASS (из `//set build-jass`). Пусто, если не настроено. |
| `{{target-as}}` | Полный нормализованный путь к файлу сборки AngelScript (из `//set build-as`). Пусто, если не настроено. |

### Пример шаблонов

```jass
//entry
//set build-jass ./out/war3map.j
//set build-before echo "Сборка из {{entry}}..."
//set build-after my-post-build.sh {{target-jass}}
```

## Поведение

* Настройки действуют только в пределах одного файла — они не
  распространяются через `//import`.
* Нераспознанные ключи принимаются без ошибок (для прямой совместимости).
* Отсутствующее значение вызывает предупреждение (warning).
